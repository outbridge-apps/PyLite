# CPython-derived conformance suite

Dialect-level conformance tests for the PyLite engine, mined from CPython's own test suite
(`Lib/test/`). Each case is a plain PyLite-dialect script whose `assert` statements ARE the test:
a case passes when the script runs to completion on the engine. This directory is deliberately
separate from `src/` and `tests/` — it tests *language semantics against CPython's documented
behavior*, not the engine's internals or the hosting boundary (those live in `tests/PyLite.Tests`).

## Layout

```
conformance/
  cases/<area>/*.py        the test cases, one topic per file (grammar, every builtin type,
                           every module the engine exposes, negative syntax/error cases)
  PyLite.Conformance/      the runner (net472 console app)
```

The `*_full.py` files exercise every member a module or type exposes; the earlier `*_core.py` files
are the seed cases and stay as smaller, faster smoke checks.

## Running

```
cd conformance/PyLite.Conformance
dotnet run -c Release              # everything
dotnet run -c Release -- str       # only cases whose path contains "str"
dotnet run -c Release -- -v        # verbose: list passing cases and tracebacks
```

Exit code 0 = no failures. A case passes when it runs to completion; the first failing `assert`
(or any uncaught error) fails the case and the runner reports the error type, line and message.
All cases run on ONE engine instance, which is deliberate: it is how the host reuses an engine for
a batch of scripts, and it is what exposed the cross-run hash-seed bug this suite found first.

## Case file directives

Leading comment lines may carry directives:

- `# skip: <reason>` — the case is not run; the reason is printed and counted. Used for documented
  dialect walls (see below), never to hide a defect.
- `# expect: <ErrorType>` — the case MUST fail, and the error's Python type (`ZeroDivisionError`)
  or engine kind (`SyntaxError`) must match. Used for negative syntax/error-surfacing cases.

## Scope and deviations

PyLite is a deliberately restricted, embeddable dialect. Constructs outside the dialect
(generators/`yield`, `async`, arbitrary imports, file I/O, ...) are asserted as compile-time
refusals in `cases/syntax/`; documented semantic deviations are asserted in their *dialect* form
with a `# dialect:` comment at the assertion. The engine's own behavioral gates — resource budgets,
hosting marshaling, concurrency — are covered by the main test suite, not here.

Known deviations surfaced by this suite (each one is asserted in its dialect form by a case):

Language
- Classes are *record classes* (RFC-001 §1): the body holds methods, field annotations, docstrings and
  constants (`NAME = value`, class attributes read through the class and its instances; an instance gets
  its own value only from `__init__` - instances keep fixed fields; of the dunders only `__match_args__`,
  `__slots__` and `__hash__ = None`), single inheritance, `super()` (also `super(Class, self)`) and
  explicit base calls (`Base.__init__(self, ...)`). `super()` in a function nested in a method has no
  arguments, as in CPython; through `super()` an `__init__` that no class above wrote is the one
  `@dataclass` generated, or `object.__init__`, and no other `object` method is reachable.
  Lambdas and comprehensions in a class body see its earlier constants (CPython hides them).
  Equality and hashing are CPython's: a bare class compares and hashes by IDENTITY, field equality
  is generated by `@dataclass` alone, `@dataclass(eq=True, frozen=False)` is the unhashable one,
  `@dataclass(frozen=True)` hashes by field values, `@dataclass(eq=False)` keeps identity on both
  sides, and a written `__eq__` without a `__hash__` takes the hash away. The generated repr is
  `Name(f=v, ...)` where CPython writes `<A object at 0x...>`, since no address is ever printed.
  The protocol methods a class may define are `__init__`/`__post_init__`/`__repr__`/
  `__str__`, `__eq__`/`__ne__`/`__lt__`/`__le__`/`__gt__`/`__ge__`, `__hash__`/`__bool__`/`__len__`/
  `__call__`, `__contains__`/`__getitem__`/`__setitem__`/`__delitem__`/`__iter__`/`__next__`/
  `__reversed__` and `__enter__`/`__exit__`; every other dunder is a SyntaxError naming the method, and there is no `object`,
  `property`, etc. `id()` is a counter rather than an address, so `id(a) == id(b)` exactly
  when `a is b`.
- `with` (one or several items, and the parenthesized 3.10 form) is CPython's protocol: `__enter__`
  and `__exit__` are both looked up before `__enter__` runs, `__exit__` gets `(type(e), e, tb)` and a
  true answer suppresses the exception, items exit in reverse. The third argument is `None`, since the
  dialect has no traceback objects. A resource limit is not an exception: it passes through every
  `with` without calling `__exit__`, so no manager can see or swallow it. `io.StringIO` and `io.BytesIO`
  are managers (leaving closes them); `async with` is refused with `async`.
- `match` class patterns: `__match_args__` is what `@dataclass` writes - the positional `__init__` names, readable
  as `Cls.__match_args__`; a plain class has none and takes no positional sub-patterns (builtin types match
  by `isinstance`, the self-matching ones take one positional sub-pattern).
- `SyntaxError` is a class a script can name and catch, and `xml.etree.ElementTree.ParseError`
  descends from it as in CPython; but nothing in the engine raises it - compile errors are an engine
  kind reported to the host before the script runs, and there is no `eval`/`exec` to produce one at
  run time. An unknown encoding is a `LookupError`.

Strings and bytes
- Case mapping is the full Unicode 16.0 mapping, from tables generated by `tools/PyLite.UnicodeGen`
  rather than from the BCL: it changes length where CPython does (`'ß'.upper() == 'SS'`), `casefold()`
  is its own mapping, and `Final_Sigma` is applied. The locale-conditional rules (`lt`, `tr`, `az`) are
  not, which is also what CPython does for the locale-independent methods. Case mapping and the `is*`
  predicates work by code POINT, so a surrogate pair maps and classifies as one character (an emoji is
  printable, a Deseret letter is cased) even though `len`, indexing and slicing still count it as two
  units - the UTF-16 model of .NET strings and SQL `nvarchar`, kept on purpose.
- `bytes` carries CPython's method surface, read as ASCII the way CPython's bytes reads it: `hex`/
  `fromhex`, `decode`, `split`/`rsplit`/`splitlines`, `join`, the `strip` family, `find`/`index`/
  `count`/`replace`, `startswith`/`endswith`, `partition`/`rpartition`, `center`/`ljust`/`rjust`/
  `zfill`, `expandtabs`, `removeprefix`/`removesuffix`, `translate` with `bytes.maketrans`, the case
  methods and the `is*` predicates. `splitlines` breaks on `\n`, `\r` and `\r\n` only, where str also
  breaks on the vertical tab, form feed, the separators, NEL, LS and PS.
- Static and class members live on the TYPE, not on an instance: `str.maketrans(...)`,
  `dict.fromkeys(...)`, `int.from_bytes(...)` and `float.fromhex(...)` all work, while
  `'a'.maketrans` and `(5).from_bytes` are an AttributeError as they are not per-value data.
  The numeric-tower attributes are there: `real`, `imag`, `numerator`, `denominator` and `conjugate()`
  on int, `real`, `imag` and `conjugate()` on float. `bool` is its own value KIND rather than an int
  subclass, but it carries int's whole method surface as CPython's does — `True.bit_length()` is 1,
  `True.to_bytes(1, 'big')` is `b'\x01'`, `bool.from_bytes(...)` works — and every answer is an `int`,
  never the bool back (`True.real` is `1`). `isinstance(True, int)` is True and `hash(True) == hash(1)`,
  so a bool and a 1 collapse to one dict key.
- Codecs are utf-8, utf-8-sig, ascii, latin-1, cp1251, cp1252, cp866, koi8-r, iso-8859-5, utf-16, utf-16-le and utf-16-be. The
  error handlers are all of CPython's: `strict`, `ignore`, `replace`, `backslashreplace`,
  `xmlcharrefreplace` and `namereplace` (the last two encode only) and `surrogateescape`. An unknown name is a `LookupError`,
  raised — as in CPython — only once a character or byte actually fails.

Numbers
- `random` is backed by `System.Random`, not MT19937: seeded SEQUENCES differ from CPython's.
  This is permanent (owner decision, re-confirmed 2026-09-08); the API contract — ranges, per-seed
  determinism within an engine version, distribution invariants — is what the cases assert.
- `decimal` keeps a coefficient and an exponent as the spec does, but the magnitude is a
  `System.Decimal`, so the context is real and the range is the backend's: `prec` and `rounding` both
  drive every arithmetic result as in CPython, and 28 digits is the ceiling (`prec` outside [1, 28] is
  a `ValueError`); `|x|` above ~7.9e28 is `Overflow`, and below 1e-28 the engine raises
  `decimal.Underflow` rather than answering the 0 the backend would give (CPython has no floor there
  and raises nothing). The exponent survives arithmetic by the ideal-exponent rules and shows in the
  repr — `Decimal('1E+2')`, `Decimal('100').normalize()` → `1E+2`, `Decimal('0.0000001')` → `1E-7`, a
  result too wide for `prec` → `1.2346E+8` — and `sqrt`, `ln`, `log10`, `exp` and a fractional `**` are
  there, correctly rounded at the context precision. Negative zero is real (`Decimal('-0')`); Infinity
  and NaN are not, so `ln(0)` raises where CPython answers `-Infinity`.
- `string.Template` and the `email.utils` date helpers are CPython's own Python source run as dialect
  code: `Template` subclasses with their own `delimiter`/`idpattern`/`braceidpattern`/`flags`/`pattern`
  as in CPython, but `Template.pattern` itself is `None` (no `__init_subclass__`); `email.utils` has
  `formatdate`, `format_datetime`, `parsedate`, `parsedate_tz`, `parsedate_to_datetime` and
  `mktime_tz` only, on the engine clock.
- `contextlib` has `suppress`, `nullcontext` and `closing` (no generators, so no `contextmanager`).
  A resource limit passes through every `with` without calling the manager, so no `suppress` can
  keep a run alive past one. `decimal.localcontext(ctx=None, prec=..., rounding=...)`,
  `setcontext` and `Context(prec, rounding)` are there; a context carries those two fields only.
- `statistics` accepts int/float/Fraction/Decimal data. A Decimal is a rational, so the exact
  summation carries it and the answer converts back with `T(numerator)/T(denominator)`, exactly as
  CPython's `_convert` does; `stdev` of Decimal data is a Decimal, `fmean` is a float. CPython's
  `_coerce` rules hold: int mixes with anything, Fraction with float, Decimal with neither.
- `strftime` is glibc's, as CPython on Linux/macOS: the flags `-` `_` `0` `^` `#`, the codes `%e %k %l %P
  %C %h %n %t %G %V %u %s %D %F %T %R %r` (`%s` reads the wall-clock fields as local time whatever the
  tzinfo, mktime-style); an unknown code stays literal, flag included. Windows CPython refuses
  `%-d`/`%s`/`%P`/`%k`/`%l` with a ValueError instead. `%Y` always writes four digits, so year 1 is
  `0001`; CPython hands the year to the platform, where glibc writes `1`. `datetime.astimezone(tz=None)` reads a naive
  datetime as local time (the host clock's fixed offset) and answers `timezone(offset, name)` for the
  local zone.
- `zoneinfo.ZoneInfo(key)` runs on the Windows time zone database: the IANA key goes through CLDR's
  windowsZones map (aliases such as `Asia/Kolkata` included, generated by `tools/PyLite.UnicodeGen`) to a
  Windows id, and offsets/DST come from `TimeZoneInfo`. Current rules match tzdata; historical dates
  are as accurate as the OS's rule history. `tzname()` answers tzdata's abbreviation for the zones that
  have one (`CET`/`CEST`, `EST`/`EDT`, `BST`, `IST`, `JST`, `AEDT`, ...) from an engine table, and
  tzdata's numeric form (`+04`, `+0545`) for the rest. `fold` (PEP 495) is there: `datetime(...,
  fold=1)`, `replace(fold=)`, the `.fold` attribute, set by `astimezone`/`fromtimestamp`/`now` when
  the instant lands on the second occurrence of an ambiguous hour, honoured by `utcoffset`/`dst`/
  `tzname`/`timestamp`, ignored by `==` and `hash` under the same tzinfo; a gap answers the pre-
  transition offset for `fold=0` and the post-transition one for `fold=1`. `available_timezones()`
  lists the keys this machine can resolve; `ZoneInfoNotFoundError` is a `KeyError`. Absent:
  `from_file`, `TZPATH` contents, `reset_tzpath`. A `time` object with a zone answers
  `utcoffset() is None`, as in CPython.
- `calendar`: `isleap`, `leapdays`, `weekday`, `monthrange`, `monthcalendar` (Monday-first),
  `month()` (the text calendar), `weekheader`, `timegm`, `firstweekday()` (always 0), the name
  sequences and the weekday/month constants, `mdays`, `IllegalMonthError`/`IllegalWeekdayError` and
  the `error` they derive from. Absent: `setfirstweekday` (module state would leak between runs),
  `calendar()`/`prmonth`/`prcal`, the `Calendar` classes and the locale variants.
- `collections`: `Counter.total()` (3.10) and `namedtuple(..., defaults=)` (3.7, rightmost fields,
  `_field_defaults`) are there; `namedtuple(module=)` is accepted and ignored.
- `traceback`: `format_exc`/`print_exc` for the exception being handled, `format_exception`/
  `print_exception`/`format_exception_only` for an exception object (the `(type, value, tb)` form takes
  the exception in the value slot), `chain=`. The text is the host's: `File "<script>", line N, in f`,
  no source line echoed. No traceback objects, so `extract_tb`/`walk_tb`/`format_tb`/`print_tb`/`limit=`
  and `TracebackException`/`StackSummary`/`FrameSummary` are absent, and so are `format_stack` and
  `print_stack`, which format the live stack rather than an exception.
- `__name__` is `'__main__'` in the script's globals, so the `if __name__ == '__main__':` guard runs.
- `textwrap`: `wrap`/`fill`/`shorten` with all of `TextWrapper`'s keyword options, `dedent`, `indent`
  (with a `predicate` callable); the `TextWrapper` class itself is absent.
- `secrets`: `token_bytes`/`token_hex`/`token_urlsafe`, `randbelow`, `randbits`, `choice`,
  `compare_digest`, `DEFAULT_ENTROPY`, over the OS RNG (`random` is not that). `SystemRandom` is absent.
- `urllib.parse`: `quote`/`quote_plus`/`unquote`/`unquote_plus`, `urlencode` (`doseq`, `safe`,
  `encoding`, `errors`, `quote_via` limited to `quote`/`quote_plus`), `parse_qs`/`parse_qsl`,
  `urlsplit`/`urlparse`/`urlunsplit`/`urlunparse`/`urljoin`/`urldefrag`, and the `ParseResult`/
  `SplitResult`/`DefragResult` namedtuples with `hostname`/`port`/`username`/`password`/`geturl()`,
  plus `unwrap`, `clear_cache` (nothing is cached here, so the call is a no-op that keeps the surface
  callable) and `scheme_chars`. The `uses_relative`/`uses_netloc`/`uses_params` lists are LIVE, which is
  CPython's extension point: appending to the first two teaches `urljoin` a scheme of its own, and
  `urlparse` and `urlunsplit` read them the same way, `geturl()` included. A module instance is built
  per RUN, so what one script teaches cannot reach the next. str only: the bytes variants
  (`quote_from_bytes`, `unquote_to_bytes`, `urlparse(b'...')`) are absent.
- `time.strftime` has no `%f`. `strptime`'s `%z` takes the 3.7+ forms (`+HH:MM`, seconds, a fraction,
  a literal `Z`); a mixed colon use is CPython's "Inconsistent use of :" for both directions where
  CPython's own `int()` slip gives an "invalid literal" for one of them. `timezone(timedelta(0))` is
  the `utc` singleton.
- `datetime`/`date`/`time.fromisoformat` take the 3.11+ grammar (basic and extended forms, ISO weeks,
  any single separator character, `,` or `.` fractions, `Z` and offsets, hour 24 rolling to the next
  day); the parser is digit-strict like CPython's C module, and `Invalid isoformat string: '...'` is
  the only wording for a grammar error while range errors keep the constructor's text.

Modules
- The module registry is flat, so a package (`xml`, `xml.etree`) is synthesized from the dotted
  registry key: its members are exactly its registered children, and importing it materializes
  them eagerly (CPython imports a submodule only when asked). All the import forms resolve.
- `re.ASCII` is applied by rewriting `\w \W \d \D \s \S \b \B` into their ASCII forms - pattern-wide,
  inline `(?a)`, or scoped by `(?a:...)` to its group; a negated escape inside a class (`[\D x]`,
  `[^\W]`) is rebuilt as the exact complement. Variable-width lookbehind is accepted (.NET).
  Three pattern forms .NET does not share with Python are rewritten as well: a possessive quantifier
  (`a*+`, `a++`, `a?+`, `a{m,n}+`, 3.11) becomes the atomic group it means, `{,n}` becomes `{0,n}`
  (.NET alone reads that brace as a literal), and `\N{NAME}` (3.8) resolves off the same Unicode
  table the lexer uses for string literals, inside a character class too.
- `json.loads` builds its values with Newtonsoft but holds the document to the RFC 8259 grammar,
  because that reader is lenient by design and has no strict mode: each token is matched against the
  raw text it came from, and any doubt goes to a full scan that answers in CPython's words. A trailing
  or empty comma, a comment, an unquoted or single-quoted name, a leading zero, `1.`/`.5`, a hex
  number, `undefined`, a `new Date(…)` constructor, a raw line break inside a string and a bad
  `\escape` are all `JSONDecodeError`, with CPython's own message and position (`Expecting value:
  line 1 column 6 (char 5)`). `NaN` and the two infinities stay, as they do in CPython, and
  `strict=False` is CPython's own parameter for control characters inside a string. A raw control
  character other than CR/LF inside a string (a tab) is accepted and kept — the reader hides it, and
  walking every string again to find one costs more than parsing a long one. A number beyond `double`
  (`1e400`) is a `JSONDecodeError` where CPython answers `inf`, and so is an integer literal above
  ~380 digits. `parse_float` and `parse_int` take any callable and hand it the number's text as the
  document spells it (`19.99` → `Decimal('19.99')`, `1e2` → `Decimal('1E+2')`, `1.50` → `'1.50'`);
  `NaN` and the infinities go to `parse_constant`'s default as in CPython. A number beyond
  `System.Decimal` (`1e40`) under `parse_float=Decimal` is `decimal.Overflow`. `object_hook` replaces
  each finished dict (innermost first, never an array), and `parse_constant` sees `NaN`, `Infinity`
  and `-Infinity` by those names and nothing else. `JSONDecodeError` carries `msg`, `doc`, `pos`,
  `lineno` and `colno`, derives `str()` from them and is constructible as `JSONDecodeError(msg, doc,
  pos)`. `dumps(default=fn)` is there: `fn` is called on an unserializable object and its answer
  serialized in turn (a stand-in that never bottoms out hits the depth cap as a `ValueError` where
  CPython recurses to a `RecursionError`). `skipkeys=True` drops a key JSON cannot spell instead of
  raising. `dump(obj, fp)` and `load(fp)` take any object with `write()`/`read()` — `io.StringIO` and
  `io.BytesIO` are the ones the engine ships, since there are no files (`load` decodes bytes as UTF-8) — and `dump` writes the document in one call
  rather than in chunks. Absent: `object_pairs_hook`, and the `JSONEncoder`/`JSONDecoder` classes
  with their `cls=`, which would mean subclassing a builtin (RFC-001 §1 inherits records only).
- `io` has the two in-memory files, `StringIO` and `BytesIO`, with CPython's surface: `read`/`read1`
  (bytes), `readline`, `readlines(hint)`, iteration and `next(f)` (a file is its own iterator), `write`,
  `writelines`, `seek`, `tell`, `truncate`, `getvalue`, `close`, `closed`, `flush` and the
  `readable`/`writable`/`seekable`/`isatty` flags; a write past the end pads with zeros. The buffer is
  capped at `MaxStrChars` and its growth is charged to the run. `StringIO` accepts a nonzero relative
  seek (`seek(-7, 2)`), where CPython raises `OSError`. Absent: `getbuffer`, `readinto` (no
  `memoryview`/`bytearray`), `detach`/`fileno`, `TextIOWrapper`, `open()`.
- `enum`: `Enum`, `IntEnum`, `StrEnum`, `auto`, `unique`, the functional form and the `(str, Enum)` /
  `(int, Enum)` mixins. Members are the class body's `NAME = value` lines; the body may also hold
  methods, `__str__`/`__repr__` and functions (not members), and nothing else. An `IntEnum`/`StrEnum`
  member is the int/str object itself, so an operation that returns its operand unchanged
  (`s.strip()`, unary `+`) hands back the member where CPython makes a plain value. `__members__` is a
  dict; a mixin's `format()` with a spec formats the value. No `Flag`, `_missing_`,
  `_generate_next_value_` or tuple values unpacked by `__init__`.
- `zipfile` works over `io.BytesIO`, the only file there is: `ZipFile(buf, mode)` reads, writes (`w`, `x`)
  and appends (`a`) STORED and DEFLATED archives, reads ZIP64 records and writes them past 65535 entries,
  and offers `namelist`, `infolist`, `getinfo`, `read`, `open` (both modes), `writestr`, `testzip`,
  `printdir`, `comment`, `ZipInfo`, `is_zipfile` and the exceptions. A path is a TypeError naming the
  missing file system, and so are `write(path)` and `extract*`. A member is read whole when it is
  opened (a later change to the BytesIO is not seen); its CRC is checked by the read that reaches the end,
  as in CPython. Inflation is charged per chunk and stops at the recorded size, the entry count is capped
  by `MaxCollectionItems`, and CPython 3.12's overlapped-entries guard refuses a member that runs into
  the next one. Duplicate names and an over-long comment are accepted without the warning CPython
  emits (no `warnings`). Absent: bzip2 and lzma (NotImplementedError), decryption (an encrypted member
  is CPython's RuntimeError without a password and NotImplementedError with one), `Path`, `PyZipFile`.
  `create_system` is 3 (CPython on unix), and a backslash in a name is kept, as there.
- `csv` takes `dialect` (positional or keyword) naming one of the three presets CPython registers at
  import — `excel`, `excel-tab`, `unix` — and the fmtparams override it: `delimiter`, `quotechar`,
  `lineterminator`, `quoting`, `skipinitialspace`, `escapechar`, `doublequote`, `strict` (plus
  `fieldnames`/`restkey`/`restval`/`extrasaction`). All of them are keywords only, and an unknown one
  is a TypeError rather than being ignored. `Sniffer` (`sniff`, `has_header`, a port of Lib/csv.py's),
  the dialect objects `excel`/`excel_tab`/`unix_dialect`, `get_dialect` and `list_dialects` are there;
  a dialect object is accepted wherever a name is. `Sniffer` guesses the quote character from the first
  64 KB of the sample rather than all of it: those regex passes cannot be interrupted, and the head
  answers the same for any real file. The delimiter frequency scan still reads the whole sample.
  A reader carries `line_num` (source lines read, so an embedded newline advances it by more than one)
  and `dialect`, a writer carries `dialect`, and a `DictWriter` carries `fieldnames`/`restval`/
  `extrasaction` while a `DictReader` carries `fieldnames`/`restkey`/`restval`/`line_num`/`dialect`
  and the inner `reader`. `writerow` returns whatever the sink's `write()` returned (3.5) and
  `writeheader` likewise (3.8); `writerows` stays None. `csv.__version__` is `'1.0'`.
  `register_dialect(name, dialect=None, **fmtparams)`, `unregister_dialect` and
  `field_size_limit([n])` are there, and both the registry and the limit are per RUN: the module
  dictionary is frozen at engine build and shared between runs, so they live on the run's context
  instead and a dialect one script registers is invisible to the next. Registering over a preset
  shadows it, as it does in CPython's single dict. A dialect may also be ANY object carrying the eight
  attributes, each absent one falling back to the default — which is what CPython's `dialect_init`
  does, clearing a missing attribute, so `csv.Dialect` there is a carrier and not a requirement and a
  record class with the fields set in `__init__` serves here. All six quoting modes are there,
  `QUOTE_STRINGS` and `QUOTE_NOTNULL` (3.12) included: both write a `None` as an empty unquoted field
  and read an empty unquoted field back as `None`, `QUOTE_STRINGS` otherwise behaving as
  `QUOTE_NONNUMERIC` and `QUOTE_NOTNULL` as `QUOTE_ALL`. `QUOTE_NONNUMERIC` quotes `None`, as
  CPython's does (`quoted = !PyNumber_Check(field)` is computed before the None branch), which is
  exactly why 3.12 added `QUOTE_NOTNULL`; a `quoting` value outside the range is a TypeError rather
  than a silent `QUOTE_MINIMAL`. Absent: the `Dialect` NAME itself to subclass, which would need class
  attributes in a class body (RFC-001 §1 has none) and a builtin base (a base must be a record class).
- `dataclasses`: `@dataclass(init=, repr=, eq=, order=, frozen=, kw_only=)`, `field(default=,
  default_factory=, init=, repr=, compare=, kw_only=, hash=, metadata=)`, `fields()` (Field.type is
  the annotation NAME as a string, or None), `asdict()`, `replace()`, `__post_init__`. An unknown
  keyword to `dataclass()`/`field()` is a TypeError rather than being ignored. `astuple()`,
  `is_dataclass()` and `make_dataclass()` (single inheritance; `namespace` entries must be functions
  defined in the script) are there. `x: InitVar[T]` is an `__init__` parameter handed to
  `__post_init__` and never stored; `x: ClassVar[T] = v` is a class attribute the machinery leaves
  alone, readable through the class and the instance.
- `typing` is annotation-tolerant: `get_type_hints()` returns a class's field annotations, and a
  function's parameter and return annotations, as the NAMES they were written with (`{'x': 'int'}`),
  the shape CPython gives under `from __future__ import annotations`; an annotation that is not a plain
  name (`list[int]`, a string) is dropped.
- `hashlib`: md5/sha1/sha224/sha256/sha384/sha512 (no sha3/blake2/shake; `hmac` covers the same six),
  plus `pbkdf2_hmac(hash_name, password, salt, iterations, dklen=None)`, written out over HMAC so the
  iteration loop charges the budget: a runaway iteration count stops on the deadline instead of sitting
  inside one native call. `struct.iter_unpack` is there, lazy as CPython's, and refuses a buffer that is
  not a whole number of records. A parsed format is cached per run (256 entries), and the integer codes
  decode through a long, so only an unsigned 8-byte value above `long.MaxValue` reaches a big integer.
  `zlib`/`gzip`: one-shot API (docs/deviations.md).
- `xml.etree.ElementTree.tostring` takes any codec the engine has as `encoding`: `unicode` gives str,
  `utf-8` and `us-ascii` give bytes without a declaration, and every other codec gets CPython's
  `<?xml version='1.0' encoding='...'?>` line with unencodable characters written as character
  references; `xml_declaration=True/False` forces it either way (a str result then declares utf-8 where
  CPython names the locale's encoding). `indent()`, `Element.iterfind()` (the findall matches, computed
  up front) and `ElementTree` (root holder; `write()` into a sink with `write()`: `io.StringIO` with
  `encoding='unicode'`, `io.BytesIO` with any other encoding, since there are no files) are there, and so are `Element.itertext()`,
  `Comment`/`ProcessingInstruction` (their tag IS the factory, as in CPython, so `e.tag is ET.Comment`
  is the test and neither answers a tag filter), `dump` (to the print sink) and `tostringlist` (one
  whole chunk). `QName` carries the `{uri}local` text and compares, orders and hashes as that text, so
  it serves as a tag, an attribute name or a dict key, and a tag written as one is stored as its text.
  `Element.makeelement` and `fromstringlist` are there. `parse(source)` and `iterparse(source, events)`
  take an object with a `read()` method — `io.StringIO` or `io.BytesIO` (read as UTF-8) — and a filename is
  a TypeError naming the reason, since there is no filesystem. `iterparse` parses the document up front
  and replays `start`/`end` from the finished tree rather than streaming: a source here is an in-memory
  object, so the text is materialised before the first event either way; `start-ns`/`end-ns` are a
  ValueError. `XMLID` and `ElementTree.parse(source)` are there too. `ParseError` carries `position`
  as `(line, column)`; `code` is expat's error number and has no counterpart here, so it is absent
  rather than invented, and the DTD refusal is worded for a script author instead of quoting the
  reader's advice about `XmlReaderSettings`. The find/findall path grammar covers CPython's documented
  subset — `tag`, `*`, `.`, `..`, `.//`, `{uri}tag`, `prefix:tag` with a `namespaces` map, `[@a]`,
  `[@a='v']`, `[@a!='v']`, `[tag]`, `[tag='t']`, `[tag!='t']`, `[.='t']`, `[N]`, `[last()]`,
  `[last()-N]` — comparing the COMPLETE text content as `''.join(e.itertext())` does, and a path it
  cannot read is a `SyntaxError` rather than an empty match set. `tostring`/`write` take `method`
  (`xml`/`html`/`text`) and `short_empty_elements`, and refuse a keyword they do not implement.
  Absent: `canonicalize` (C14N 2.0), `XMLParser`, `TreeBuilder` and `XMLPullParser`, so `parser=` is
  refused rather than ignored, and `default_namespace=`.
- `bisect` (searches on a list or tuple, `insort` on a list, `lo`/`hi`/`key`), `string` (the
  constants and `capwords`; no `Template`/`Formatter`, which need a class to subclass), `heapq` (the
  heap functions, `nlargest`/`nsmallest`, and `merge` with `key`/`reverse`, lazy as CPython's: an
  infinite input costs what is consumed) and `operator` (the operator
  functions, `itemgetter`/`attrgetter`/`methodcaller`; no in-place `i*` forms, no `matmul`,
  `length_hint` or `call`) are present.
- `unicodedata`: `normalize`/`is_normalized` (the four forms, through the BCL's normalizer - the OS
  NLS tables on net472, older than Unicode 16.0 for the newest characters; a lone surrogate passes
  through as in CPython), `name`/`lookup` (the engine's own Unicode 16.0 name table, aliases and named
  sequences included), `category`/`numeric`/`decimal`/`digit` (from `CharUnicodeInfo`, the BCL's
  Unicode version), `east_asian_width`/`combining`/`bidirectional`/`mirrored`/`decomposition`
  (generated Unicode 16.0 tables; an unassigned code point has bidi class `''`, as in CPython).
  Absent: `ucd_3_2_0` (the IDNA snapshot, which nothing here consumes). One `Normalize()` call is
  quadratic in its own length on Windows, so a string over 4096 characters is normalized in chunks cut
  where a split cannot change the answer (a starter that is never the second half of a composition).
  A sequence longer than 8192 characters offering no such point - a base character followed by
  thousands of combining marks - raises `ValueError` instead of running; CPython normalizes it.
